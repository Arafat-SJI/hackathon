## Application architecture

### Layers

Describe how the application is structured into layers, for example:

- **Presentation/UI** – pages, components, and routing.
- **Application/Services** – orchestration, workflows, and use-cases.
- **Domain** – core business logic and rules.
- **Infrastructure** – data access, external APIs, messaging.

### Module boundaries

- Define feature modules (e.g., auth, patient-management, reporting).
- Document allowed dependencies between modules and layers.

### Cross-cutting concerns

- Error handling.
- Logging and monitoring.
- Caching.
- Security and authorization.

Keep this document updated when you introduce new modules or refactor boundaries.
